GIL（Global Interpreter Lock） 是 CPython 解释器中的一把互斥锁，保证同一时刻只有一个线程在执行 Python 字节码。其设计初衷是保护解释器内部数据免受并发访问破坏，因为 Python 的对象管理和垃圾回收基于引用计数，非线程安全。GIL 使得多线程在 CPU 密集型任务中几乎无法利用多核优势，甚至可能因锁争用导致性能下降。但在 I/O 密集型场景中，线程在等待 I/O 时会释放 GIL，故多线程仍能提升效率。

为了在单线程内实现高并发，Python 提供了 asyncio 库。它采用事件循环（Event Loop）加协程（Coroutine）的模式。通过 async/await 语法，协程可以在 I/O 操作处挂起，将控制权交还给事件循环，转而执行其他协程，从而在单个线程内完成大量并发任务。由于不存在多线程，GIL 完全不会影响 asyncio 的执行效率。

python
import asyncio

async def fetch(url):
    print(f"开始请求 {url}")
    await asyncio.sleep(1)       # 模拟 I/O
    print(f"完成请求 {url}")
    return f"{url} 的数据"

async def main():
    tasks = [fetch(f"/api/{i}") for i in range(3)]
    results = await asyncio.gather(*tasks)
    print(results)

asyncio.run(main())
上述代码在同一个线程内交替执行三个 fetch 协程，仅需约 1 秒完成。若用多线程实现相同功能，虽然可行，但要处理锁、线程安全等问题，而 asyncio 则提供了更轻量级的解决方案。

总结：GIL 限制了 CPU 密集型多线程的并行性，此时可改用多进程（multiprocessing）或 C 扩展；I/O 密集型并发则可在多线程和 asyncio 之间选择，asyncio 因其单线程协程模型，天然避免了 GIL 的困扰，适合高并发网络服务。
