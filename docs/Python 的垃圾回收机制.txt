Python 的内存管理主要依赖引用计数和分代回收（Generational Garbage Collection）。每个对象内部维护一个引用计数，当计数降为零时，对象立即被销毁，内存释放。这种机制具有实时性和确定性的优点，但无法处理循环引用——例如两个对象相互引用，即使外部已无法访问，引用计数仍不为零，导致内存泄漏。

为解决这一问题，Python 引入了一个可选的循环垃圾回收器。它会定期扫描对象，通过标记-清除（Mark and Sweep）算法检测不可达的循环引用组并将其回收。为了减少扫描开销，回收器采用了分代策略：将对象划分为年轻代（0 代）、中年代（1 代）和老年代（2 代）。新创建的对象进入年轻代，存活过多次回收的对象会被提升到更老代。由于多数对象生命周期短暂，垃圾回收会频繁检查年轻代，而较少扫描老年代，从而提高了效率。

python
import gc, weakref

class Node:
    def __init__(self, val):
        self.val = val
        self.other = None

a = Node(1)
b = Node(2)
a.other = b
b.other = a   # 循环引用

del a, b      # 此时引用计数非零，但对象已不可达
gc.collect()  # 手动触发循环回收，内存被释放
你可以通过 gc 模块查看和调优回收行为，例如 gc.get_threshold() 查看分代阈值，gc.disable() 禁用自动回收。为避免循环引用，也可以使用 weakref 模块创建弱引用，不增加引用计数。

垃圾回收虽然自动，但理解其原理有助于优化内存使用。在处理大规模对象、闭包或事件监听器时，循环引用常常是内存泄漏的来源，合理使用弱引用或显式打破环是关键。
